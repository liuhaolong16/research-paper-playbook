## 二、★ 2 条真未处置（本轮补上）

### 未处置 1 · 可执行型 #3「前人对照表字段未定义」

**红队原话**：未给字段定义，「对照」是数值还是结论、测试条件是否归一化未定；不同热处理制度下硬度值并列即错。
**为什么漏了**：v0.5 修订 ④ 我只补了「二次数据专用清单」，**那是「数据来源」的字段，不是「前人对照表」的字段** —— 两件事被混为一谈。
**⇒ 补：前人对照表冻结列（8 列，末列必填）**

```
| 文献（作者年） | 材料牌号 | 工艺条件 | 测试标准 | 数值 ± 误差 | n | 是否可比 | 不可比原因（★ 必填） |
```

**规则**：
- **工艺条件列不允许留空**（不同热处理制度的硬度值并列 = 误导）
- **测试标准不同 ⇒ 必须在末列写明差异**（如 ASTM E384 vs GB/T 4340）
- **「是否可比」为否时，该行数值不得用于本文的定量比较**，只能作定性引用

### 未处置 2 · 可执行型 #7「04 数据库未指定工具与版本控制，剔除异常值无留痕」

**红队原话**：未指定工具与版本控制，剔除异常值无留痕要求。
**为什么漏了**：04 维度写了「目录结构」「命名规范」「元数据 8 项」，**但没写「用什么工具做版本控制」与「剔除数据必须留痕」**。
**⇒ 补：数据版本控制与剔除留痕**

```
版本控制三件套（最低要求）：
1. 原始数据：raw/ 目录 + 校验值（SHA256），不覆盖不编辑
2. 处理脚本：scripts/ 目录，脚本本身也进版本控制（Git 或最简：带日期的手工版本号）
3. 变更记录：CHANGELOG.md，每次处理写「日期 + 脚本版本 + 参数 + 影响了哪些结果」

剔除数据必须留痕（四项）：
1. 被剔除点的原始值
2. 依据哪条规则（预先定义的规则，见维度 10.6）
3. 剔除前后的 n
4. 结论是否因此改变（改变则两个结论都报）
```

## 三、本轮结论

> **机械化审计找到了 2 条真人眼会漏掉的未处置条目。**
> **原因不是记性差，而是「同名前缀的条目被混为一谈」** ——
> 例如「字段未定义」在数据来源与对照表上各出现一次，处理了一个就以为处理了两个。
**⇒ 纪律**：**同名前缀的条目必须分别编号核对**（如 #3「对照表字段」≠ v0.5 修订 ④「二次数据清单」）。
