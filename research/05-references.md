## 一、检索策略（与 04.3 互补，此处聚焦「找全」与「判断饱和」）

**四步法**：
1. **种子集**：从最近的 3–5 篇同主题综述 + 目标刊近 2 年同主题论文起步
2. **向前追溯**（backward）：读种子集的参考文献表 → 找奠基文献
3. **向后追溯**（forward）：用引文索引查「谁引了种子集」→ 找最新进展
4. **饱和判断**：当「向前 + 向后」两轮都不再出现新文献时停止（A2 稿给的量化判据：新增相关文献 < 总量 5%）

**必须留痕**：库名、检索式全文、日期、命中数、纳入数 —— **没有留痕的检索 = 不可复现的检索**。

## 二、文献管理的工具链（分工明确，别混用）

| 环节 | 工具类型 | 要求 |
| --- | --- | --- |
| 检索与抓取 | 数据库 / 学术搜索 | 导出为通用格式（.bib / .ris），**不手工录条目** |
| 去重与归档 | 文献管理软件（Zotero / EndNote 类） | 全项目用一个库；含 PDF 与笔记 |
| 引用与格式化 | 管理软件的插件 | **格式由软件生成，不手打**；换目标刊时一键切格式 |
| 版本与备份 | 同步 + 本地备份 | 文献库是要长期维护的资产，**丢了等于重做** |

**★ 一条纪律**：**从第一次检索起就用管理软件**。写到一半才整理的代价，比一开始就整理高一个量级。

## 三、引用规范

- **国内学位论文**：GB/T 7714（**具体版本与本校要求须现查**），通常要求「顺序编码制」
- **SCI 论文**：**以目标刊 Author Guidelines 为准**，各刊差异大（作者数上限、期刊名缩写与否、DOI 是否必给、et al. 的用法）
- **通用底线**：
  - **正文引用与文献表一一对应**（多一条、少一条都是形式审查的硬伤）
  - **不引你没读过的文献**（引文内容错误会被审稿人抓住）
  - **二手引用要标明**（「转引自」）—— 除非你核对了原文
  - **预印本、会议摘要、网页**要标明类型与访问日期

## 四、文献综述的写法（这是本维度最见功力的部分）

### 结构：按【主题/机制线索】聚合，不按时间罗列

**错误写法（编年体）**：
> 2018 年 A 等人研究了…。2019 年 B 等人研究了…。2020 年 C 等人研究了…。

**正确写法（主题体）**：
> 关于 X 对 Y 的作用，存在两种解释：一类工作（[A], [B]）支持…；另一类（[C]）报道相反结果，其条件差异在于…。
> **本文针对的正是这个分歧。**

### 综述表（把「读了多少」变成「读出了什么」）

| 作者（年） | 体系 | 方法 | 主要结论 | 不足 / 未覆盖 |
| --- | --- | --- | --- | --- |
| … | … | … | … | … |
| **本文** | | | | ← **最后一行写自己，一眼看出区别** |

### 常见硬伤

| 硬伤 | 症状 |
| --- | --- |
| **流水账** | 每篇一段，彼此无关联，读完不知道领域状态 |
| **只用一句话概括一篇** | 丢掉了条件、方法、限制——而这些正是对比的抓手 |
| **只引结论一致的工作** | 回避反证；**审稿人会认为作者没掌握现状**（Red 组 A11/组 7） |
| **自引过高** | 自引 >25% 会被判「圈子互引」（Red 组 7）；**>20% 主动补引** |
| **缺奠基文献** | 清一色近 5 年，说明没追溯 |
| **综述章与后文脱节** | 综述里反复出现的概念后文不用（Red 组 A10） |
| **gap 写「尚无人研究」** | 只要有一篇反证文献就站不住；**必须写成「争议」或「条件缺口」** |

## 五、验收判据

> **★★★ 判据质量十七条（跨维度通用 · Round 138 补 · 每条都来自本方案自己的踩坑）**
> **⇒ 为什么插在这里**：**对抗审查者（Round 133）用机械探测查出 —— 有 8 条**关于判据本身质量**的修正，**在 11 个维度里零命中**** ⇒ **读者按维度执行时看不到它们，方法论成了只被作者阅读的层。** **⇒ 现把它们收回维度内。**
> **⇒ 用法定级**：**下面八条是**判据的判据** —— 你自己写验收项、设阈值、做检查清单时，**先过这八条**。**

| # | **规则** | **一句话用法** |
| --- | --- | --- |
| **1** | **只有反例的清单会失去区分力**（修正二） | **清单里既要有反例也要有正例** —— 全是「不要怎样」，读者无法判断「做对了是什么样」 |
| **2** | **判据必须「范式感知」**（修正二十） | **每条判据声明适用范式**（例：理论 / 计算类不适用「报 n」） |
| **3** | **判据必须「平台感知」**（修正二十一） | **阈值须注明在哪些平台验证过** —— 同一判据在不同出版平台可能给出**相反**结论 |
| **4** | **判据要「可检出率」感知**（修正二十二） | **≈100% 才能做「缺一即不合格」的门槛；70–99% 只能做提示；<70% 不可用** |
| **5** | **阈值太松 = 没有区分力**（修正十七） | **一个永远合格的阈值不产生信息**；且**阈值必须绑定可执行动作**，只给数字不给动作等于无效 |
| **6** | **从不改变决定的判据，不该当闸门**（修正二十九） | **自检**：**这条判据**有没有可能判出「不合格」**？**从来没有 ⇒ 它只是仪式，删掉或降为提示 |
| **7** | **会「误报」的闸门，与会「漏报」的一样有害**（修正四十七） | **凡闸门须用**两侧样本**验**（一组已知合格 + 一组已知不合格）；**阈值与工具绑定 ⇒ 换工具必须同期重标定** |
| **8** | **验收判据要与「失败形态」配对**（修正四十六） | **判别式**：**第二个人**不看你的稿**，能不能说出「什么算不合格」**？**不能 ⇒ 这条判据还没写完** |

| **9** | **「端到端干跑」是一种独立的验证手段**（修正二十七） | **每个交付物至少真跑一遍全流程** —— **查静态文本不算**；**干跑会发现只看文本看不出的问题**（页面溢出、脚本报错、字段对不上） |
| **10** | **检查器对「被检查的」与「当参照的」用了不同规则**（修正三十三） | **你把 X 和 Y 对比时，**X 与 Y 是否按同一规则被处理**？**不同 ⇒ 结论无效**（本方案实测过：同一个数与两个不同基准比，得出相反结论） |
| **11** | **一次反向测试只能证明「它能报错」，不能证明「它的判据足够严」**（修正五十三） | **做**分级反向测试**：轻度削弱（删一个实例）与重度削弱（删整块）**都试**；**若轻度削弱下仍通过 ⇒ 说明它只要求「存在」不要求「普遍」**** ⇒ **要明确写出这门在防什么** |
| **12** | **「缺失断言」必须指明它相对于哪个输出流**（修正五十四） | **空流会让一切「没找到 X」的断言通过** ⇒ **正负锚必须取自**同一输出流****；**★ 并**保留选错的锚**，以区分「判据报警」与「锚选错了」** |
| **13** | **先证明指标测的是「被测对象」还是「测量链上的某一环」**（修正五十五） | **看**峰的位置****：**若 53% 的值挤在某个宽度上，而那个宽度是**上游工具的**参数**（如提取器的换行宽度）⇒ **你测的是上游**；**小 n（<30）不要用 CV，直接看直方图形状** |
| **14** | **「唯一来源」与「独立检验」在同一进程内不可兼得**（修正五十六） | **唯一来源 ⇒ 自检**恒过**（修正四十三）；**独立构造 ⇒ 必须复制 ⇒ 会漂移**（修正四十九）** ⇒ **三条出路**：①接受「非独立但**会失败**」的自检（只测内存以外的对象，如磁盘回读）；②**把独立检验移到另一次运行 / 另一个进程**（**这才是正解**）；③若必须同进程独立，**让第二个实现尽量小** |
> **★★★ **正向形式通则（Round 143 补，采纳自同行 月流）**：**凡验收项写的是**否定式**（「不得出现 X」「避免 Y」），**在它旁边写一行 `✓ 正向：<可观察的合格状态>`**。**⇒ 理由（同行原话）**：**「没有正向形式的准入条件只是又一次『我不想要坏的』，但不知道什么是好的。」** **⇒ ★ 本项目实测**：**十一维度 87 个验收项里，纯否定式只有 **3 条（3.4%）**** —— **本项目的验收项**绝大多数本来就是正向可观察的****（**这正是此前几轮「把验收判据写实」累积的结果**）。**⇒ 所以本通则**不是**要去批量改写，而是**给以后新写的验收项立个格式**：**写成否定式时，顺手补正向等价。**

| **15** | **采纳外部建议前，先核它的「前提」在本项目是否成立**（修正五十七） | **把建议翻译成一个可普查的判据**（如「含否定词的验收项占比」），**先量一遍再决定改不改**；**★ 量出来远低于建议者假设 ⇒ 处置定为「立格式」而不是「批量修」**；**★ 普查脚本本身要先自证**（实测：初版把「别人」当否定词，差点去「修」一条本来正确的条目） |
| **16** | **查重工具自身的漏检率，就是「重复」这件事的真实概率**（修正五十八） | **查重说「无匹配」只等于「按你给的那几个词没找到」**，**不等于「没有重复」** ⇒ **判据**：① **查重结果必须与「库里总条数」一起读**（**工具说「无匹配（共 N 条）」时，真问题是「N 条里我为什么确信都不相关」**）；② **★ 补救：未命中时再看一遍全量清单**（**成本几十行，收益是避免一次同题并存**）；③ **★ 判「同题」看**意图**不看**措辞****；④ **发现同题后不要删** —— **加 `superseded` 标记指向后继，并**保留旧条仍成立的部分** |
| **17** | **编辑「被程序消费的源文件」前，先确认它的**边界约定****（修正五十九） | **「内容对不对」与「它会不会被读到」是两个独立问题** ⇒ 判据：① **动手前先问这个文件里有没有「程序看的标记」，边界是哪一侧**；② **★「挪到末尾」是危险默认动作** —— **在有边界约定的文件里，末尾恰恰可能是被切掉的那一侧**；③ **★ 每次「看起来等价」的重写都可能**复制不该复制的东西**** ⇒ **切分时先定位标记、明确「标记只留一份且放最后」，不要按语义描述切** |
> **★★ 一条更高层的（它管的是**你做检查这件事本身**）：**
> **⇒ **机械检查的红灯与绿灯都必须交叉确认**（修正十四）** —— **绿灯也要用另一条独立路径复核**，**因为「全部通过」可能只说明检查本身失效**（本方案实测过两次：一次是检查只问「有没有缺口」不问「有没有重复」，一次是流水线被截断后仍打印成功）。**
> **⇒ **判别式**：**你的这套检查，**有没有可能「全部通过」而实际有问题**？**答不出来 ⇒ 它还没被验证过。****

- [ ] 检索式全文与命中/纳入数已落盘，**别人能照着重做一遍**
- [ ] 每个结论性陈述都有对应文献；**没有无出处的断言**
- [ ] 文献综述表已完成，**末行是「本文」**
- [ ] 已检查**自引比例**（>20% 则补引）
- [ ] 引文格式由软件生成，**全文一致**；与目标刊/本校要求逐项比对过
- [ ] **正文引用与文献表完全对应**（逐条核对，双向）
- [ ] 所有「首次/未见报道」都标注了检索库、日期与关键词（与维度 08 联动）
- [ ] **没有引用自己没读过的文献**
- [ ] **每条引用都标出了它在句中承担的作用**（背景 / 依据 / 对比 / 反例，见 §5.17 一）；作用与引文实际覆盖范围不符的已改。
  - **✓ 正向：随手抽 10 条引用，能逐条说出它的作用类别，且该类别与引文实际内容一致**
- [ ] **引用只取「作者明确陈述」与「作者解释」两类信息**（§5.17 三）；分析推断已注明属本文推断，未能确认的主张已删或写明未能确认。
  - **✓ 正向：每条引用的来源类别可回溯（引文原文 / 作者解读），推断类句子带「本文认为 / 本文推断」字样**

## 写法示例（Round 37 补）

> **为什么补这一节**：机械审计发现本维度 **5,405 字节、示例 0 处**。

### 例 1 · 引用要「带立场」，不能只点名

- **✗ 不要**：「Zhang 等[3]研究了该合金的时效行为。」（只说别人做了什么）
- **✓ 应该**：「Zhang 等[3]报道峰值硬度在 150–180 ℃，与本文的 175 ℃ 一致；但其升温速率为 50 ℃/min，**未讨论速率对峰值温度的影响**。」

**⇒ 引用要说明：本文与它是什么关系（一致 / 不同 / 它漏了什么）。**

### 例 2 · 综述表的末行必须写「本文」

| 作者（年） | 体系 | 方法 | 主要结论 | 未覆盖 |
| --- | --- | --- | --- | --- |
| Zhang (2019) | Al-Cu | 硬度 + XRD | 峰值 150–180 ℃ | 未控升温速率 |
| Li (2021) | Al-Cu-Mg | TEM | 第二相为 θ′ | 未报道重复数 |
| **本文** | Al-Cu | 硬度 + XRD（3 速率） | **速率使峰值温度移动** | 未做原位表征 |

**⇒ 末行填不出来 ⇒ 选题还没定清**（回到维度 01）。

### 例 3 · 「首次 / 未见报道」的写法（风险最高的一句）

- **✗ 不要**：「未见相关报道。」（无检索依据，且极易被审稿人一篇文献推翻）
- **✓ 应该**：「截至 2026-10-08，在 Web of Science 以 TS = (Al-Cu AND aging rate) 检索（2015–2026），未检出同时报道三种升温速率的文献；受限于无机构订阅，检索未覆盖 Scopus。」

**⇒ 写明：检索库 + 检索式 + 时间范围 + 局限性。无法给出这些要素时，不要写「首次」。**

### 例 4 · 格式差异（跨刊事实）

**⇒ 参考文献格式与数量上限必须逐刊确认** —— 已核实的三本刊在篇幅/图件要求上各不相同（见 `../期刊投稿要求核实清单.md`），**参考文献格式同理，不要套用任何模板**。

- **【答辩线】** 常按本校模板（GB/T 7714 居多），数量 **以本校研究生院文件为准**。
- **【SCI线】** 按目标刊指定格式，**以目标刊 Guidelines 为准**，且**必须含近 3–5 年**。

## 5.8 ★ 实测：References 节本身的可检出率（Round 78 补）

> **为什么补这一节**：**本维度讲怎么写参考文献，但没讲「怎么确认参考文献节确实存在且完整」。**

### 实测结果（5 篇真实论文，两种检测方法）

| 方法 | References 节检出率 | 强度裁定 |
| --- | --- | --- |
| 纯关键词 `t.includes` | 3/4 | — |
| 编号标题 + 白名单 | **4/5** | **只能作提示，不能作「缺一即不合格」的门槛** |

**根因**：**章节标题在 PDF 里的编码方式因文件而异**（字体/字号不同），提取时可能丢失或错位。

### ★ 本节给本维度加的可执行动作

| 动作 | 判据 |
| --- | --- |
| **1. 自动查只能当提示** | 脚本查不到 References ≠ 论文没有 References —— **必须打开排版成品目视确认** |
| **2. 完整性人工核** | **正文引用的编号集合 ⊇ 参考文献列表的编号集合**（正文引用但列表缺失 = 硬伤；列表有但正文未引用 = 冗余） |
| **3. 与投稿系统交叉验证** | 多数期刊投稿系统会**自动校验引用**，其报错比自建脚本可靠 |

**⇒ 出处**：`../playbook/99-methodology.md` 修正二十二（判据须可检出率感知）；实测见 `_refs/structural-test-v3.json`。

## 5.9 ★★ 投稿前必查的三件事（Round 102 补）

> **为什么补这一节**：本维度讲了「文献怎么找、怎么引、怎么写综述」，但**没讲「引到的东西本身可不可信」**。
> **⇒ 而这一层是**投稿前的最后一道闸**：前两层做完却漏了这一层，整篇文章会被一条假文献或一本掠夺性期刊废掉。**

### 一、★ AI 编造参考文献 = **学术不端**（不是「小错」）

**【已核实】** AIP Publishing 的 AI 政策明文把「AI 生成的、实际不存在的参考文献」列为**伦理违规**。
**【已核实】** Elsevier 政策要求作者对 AI 辅助产出的全部内容承担**完全责任**。
**⇒ 两者合起来的含义：**用 AI 生成参考文献，一旦有条目不存在，**责任 100% 在你，不在工具**。****

**⇒ 可执行判据（逐条，不能抽查）：**

| # | 动作 | 判据 |
| --- | --- | --- |
| **1** | **每一条文献都在数据库里查到过** | 有 DOI 的按 DOI 查；**查不到 ⇒ 直接删**（不要「大概是这个」） |
| **2** | **每条文献的作者 + 年份 + 期刊 + 卷页与数据库记录逐字对照** | **AI 最典型的失败是「作者和标题对、但期刊/年份是编的」** |
| **3** | **不引你没读过原文的文献** | 只读过摘要 ⇒ 引用时只写摘要支持的那部分，不写全文结论 |
| **4** | **★ 禁止把 AI 生成的文献表直接粘进投稿文件** | 哪怕只留一条，也必须逐条人工核过 |

**⇒ 一句话：**参考文献表里**不允许存在任何一条你无法当场打开原文（或至少打开数据库记录）的条目**。**

### 二、★ 期刊可信度：投稿前按权威清单过一遍（**免费、10 分钟**）

**【已核实】** Think. Check. Submit. 是 **ALPSP / AUP / COPE / DOAJ / ISSN / LIBER / OAPEN / OASPA / STM / UKSG 十家机构联合**发起的跨行业倡议。
**⇒ 出处**：<https://thinkchecksubmit.org/journals/>（**有简体中文版**：<https://thinkchecksubmit.org/journals/chinese/>）

**它的 7 组问题（原文结构，本方案原样转述）：**

| # | 问题组 | 关键判据（本方案挑出的最硬几条） |
| --- | --- | --- |
| **1** | **你或你的同事知道这本刊吗？** | **刊名唯一、不能与另一本刊混淆**；能在 **ISSN portal** 交叉核对 |
| **2** | **能轻松找到并联系出版社吗？** | **电话号码 / 邮箱 / 邮寄地址**都要能联系到 |
| **3** | **刊是否明确说明用哪种同行评议？** | **★ 期刊不得承诺录用，也不得承诺极短的评审时间** |
| **4** | **文章是否被专门的服务索引 / 归档？** | 是否可被检索到；**是否承诺长期数字化保存**；**是否使用持久标识符（DOI 类）** |
| **5** | **费用是否清楚？** | 说明**收什么费、什么时候收、什么币种、有没有减免**；**说明财务来源** |
| **6** | **出版社网站是否给作者指南？** | 许可政策 / 版权归属 / **利益冲突政策** / 可获取格式 / 使用与引用指标 |
| **7** | **出版社是否是公认行业倡议的**现成员**？** | **COPE 成员** · **DOAJ 收录**（OA 刊）· **OASPA 成员** · 区域平台（AJOL / Scielo / Latindex / Redalyc / INASP Journals Online） |

**⇒ 使用方式（原文那句话很重要）：**只有当你能对**大部分或全部**问题回答「是」时，才提交。**
**⇒ 反面：**任何一组答不上来 ⇒ **不要投**；尤其第 3 组（承诺录用/承诺极速评审）与第 7 组（查不到任何成员身份）。**

### 三、★ 撤稿核查：引用之前的最后一遍

**⇒ 为什么必须查：**引用了已被撤稿的文献，**等于把已被否定的结论搬进自己的论文**；审稿人一旦发现，**整篇的可信度受损**。
**⇒ 而撤稿是**持续发生**的 —— 三年前查过是对的文献，现在可能已被撤。**

| # | 动作 | 说明 |
| --- | --- | --- |
| **1** | **每条引用前查一次该文献的当前状态** | **【须查证】** 具体工具与判定依据**动笔前现查**（不同出版社的撤稿标记方式不同，本方案不给统一判据） |
| **2** | **★ 撤稿标记在 PDF 上可能看不见** | **必须在**出版方官网/数据库的条目页**看，不能只看你手上那份 PDF** |
| **3** | **已撤稿但仍需讨论的** | **明确写出「该文已被撤稿」**并说明为什么仍要提它（通常是为了指出该结论已被否定） |

**⇒ 与本维度第三节纪律的一致性：**不引你没读过的文献 ⇒ **扩展为「不引你不确认其当前状态的文献」。**

### 四、★ 引文操纵的红线（不要踩，也不要被卷入）

**【已核实——存在性】** COPE 有一份专门的立场文件 *Handling citation manipulation*：
<https://publicationethics.org/guidance/cope-position/handling-citation-manipulation>
（**该页在抓取时返回 403（Cloudflare），本条只核实了「该立场存在及其标题」，未抓到正文；引用前请自行打开核对**）

**⇒ 本方案据常见审稿关切给出的判据（【作者判断】）：**

| 红线 | 判据（可自查） |
| --- | --- |
| **自引过高** | **>20% 主动补引**；**>25% 会被判「圈子互引」**（与第四节「常见硬伤」表同一判据） |
| **互引集团** | 与同一批作者之间形成**闭环互引**（你引他、他引你、集合很小且稳定） |
| **无关引用** | 引了**对本文结论没有作用**的文献（凑数型引用） |
| **被迫引用** | **审稿人要求你引他的文章** ⇒ **可以照办，但要在回复信里说明「应审稿人建议补充」** |

**⇒ 最后一条尤其重要：**它是一种**保护自己的记录** —— 万一该审稿人被查，你有据可查。****

### 五、本节给本维度加的验收项（接到第五节清单后）

- [ ] **每一条参考文献都能当场打开原文或数据库记录**（AI 编造的条目**零容忍**）
- [ ] **投稿目标刊已按 Think. Check. Submit. 的 7 组问题过一遍**，**大部分/全部答「是」**
- [ ] **每条重点引用都已确认当前状态**（未撤稿 / 已撤稿并已标注）
- [ ] **自引比例已算**（>20% 补引）
- [ ] **若有「应审稿人建议」的补充引用，已在回复信中留痕**

**⇒ 出处**：AIP Publishing AI 政策（本方案实抓，见 `../期刊投稿要求核实清单.md`）· Elsevier 生成式 AI 政策（同上）· Think. Check. Submit.（2026 实抓）· COPE *Handling citation manipulation*（**仅核实存在性，正文未抓**）。

## 5.10 ★★★★★ 国标**版本更替**：GB/T 7714—2025 已生效（Round 132）

> **★★★★★ 本节的首要结论是一条**更正**：**
> **⇒ 本方案此前引的是 **GB/T 7714—2015**。**
> **⇒ 而《信息与文献 参考文献著录规则》**新版是 **GB/T 7714—2025**，**自 **2026 年 7 月 1 日**起正式实施**。**
> **⇒ 以本方案当前的日期（2026-10）计，**新国标已生效** ⇒ **论文若按 2015 版的著录规则写，是引用了**已被取代**的标准。**
> **⇒ ★ 因此本维度新增一条判据：**引用标准前先查「现行版本」**（详见本节第五部分）。**

**⚠ 证据边界（必须先读）**：
- **本节内容来自**二手整理**（科学出版社官方号转载、**标注来源为同济大学图书馆**的文章），它**逐条给出了新国标的类型标识与完整示例**，但**不是标准原文**。
- **该文末尾自述**：「完整、权威的著录规范请参考**全国标准信息公共服务平台**后续发布的官方原文。」
- **⇒ ⇒ 因此本节的定位是**：**「知道新版存在 + 知道新版改了什么方向 + 可用示例」**；**正式提交前必须对照**官方原文**逐项核准**（本节第五部分的判据就是为此而设）。**

### 一、★★★★★ 新国标最实质的变化：**两个新的文献类型标识**

| 类型 | 标识（2025 版） | 说明 |
| --- | --- | --- |
| **预印本** | **★ `PP`** | **`arXiv` / `ChinaXiv` / `bioRxiv` / `medRxiv` / `PSSXiv` 等平台上**尚未正式发表**的论文** |
| **数据集** | **★ `DS`** | 依托图书/期刊正式刊发的走图书/期刊格式；**其余按数据集著录** |

**⇒ ★★★ 这两个标识在 2015 版里**没有** —— 也就是说：**在此之前，预印本与数据集只能被硬塞进 `[EB/OL]` 或 `[J]`**，**这会掩盖「它尚未同行评审」这一事实**。**
**⇒ ⇒ **对两条线的意义**：
- **SCI 线**：**材料/计算领域大量使用 arXiv 预印本** ⇒ **`[PP]` 让「这是预印本」在文献表里**显式可见****（关系到**优先权**与**可引用性**的判断，见本维度已有的预印本讨论）。
- **答辩线**：**预印本与数据集**是否允许进参考文献表，**各校规定不同** —— 但**有了正规标识，至少能写得规范**。

### 二、★★★★ 三条**著录前自查**（新国标强调的判据）

| # | 原则 | **落到稿子上的动作** |
| --- | --- | --- |
| **1** | **★ 判定文献**本体类型**，而非**获取渠道**** | **先问「它是什么」，再问「我从哪拿到的」** —— **网络首发/在线获取的期刊论文仍标 `J/OL`，不是 `EB/OL`** |
| **2** | **★ 区分在线载体标识 `OL`，不混用网页格式** | **`OL` 只是「联机在线获取」的载体标识，**文献类型仍由前置标识决定****：<br>**在线期刊论文 → `[J/OL]`** · **在线报告 → `[R/OL]`** · **在线数据集 → `[DS/OL]`** · **普通网页 → `[EB/OL]`** |
| **3** | **★ 补充可追溯信息** | **① 日期**：写清**创建/发布/修改日期**，需要时补**引用日期**；**② 访问路径**：指向**具体资源页面**，**不是平台首页**；**③ 永久标识符**：有 **DOI / CSTR** 就保留 |

**⇒ ★ 第 3 条的「指向具体资源页面而不是平台首页」是一条**很实务*的判据 —— 它直接决定审稿人/答辩老师**能不能点开找到那一条**。**

### 三、★★★★★ 责任者（作者）的著录规则

| 情形 | 规则 |
| --- | --- |
| **中文姓名** | 按**文献原文**著录，**一般不加国籍、朝代**等说明 |
| **汉语拼音人名** | **姓全著录、首字母大写**；**名一般用全称且首字母大写** |
| **西文人名** | **姓全著录、首字母大写**；**名可取首字母且大写**，**名之间保留空格** |
| **★ 责任者数量** | **不超过 3 个时**全部著录**；**超过 3 个时**著录**前 3 个**，后加 **「等」**（中文）或 **`et al`**（西文） |
| **无责任者文献** | **顺序编码制下**，无责任者或责任者情况不明的，**可直接从题名开始著录** |
