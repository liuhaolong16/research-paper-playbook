## 一、理论框架 vs 概念框架

| 项 | 理论框架 | 概念框架 |
|---|---|---|
| 是什么 | 已被验证的因果模型，你借它推演 | 你自己画的关系网，说明"研究哪几个量、怎么连" |
| 来源 | 教科书 / 综述里的成熟学说 | 你综合文献后自行搭建 |
| 回答什么 | 为什么会有这个现象 | 这次测什么、按什么顺序测 |
| 检验什么 | 理论本身是否成立 | 你的操作化是否闭合 |

**什么时候用哪个**：材料 / 冶金方向的本科毕设与常规研究型 SCI，主框架几乎都是**概念框架**——你研究的是"工艺—组织—性能"，没有哪个成熟理论能整包预测；理论框架只在解释机理那一层借用（如相变热力学、扩散动力学、位错强化理论）。
- 判据式选择：结论句形如「某参数导致某性能变化」→ 用概念框架；形如「某理论预测……实测偏离，因为……」→ 需要理论框架。
- 【答辩线】评委问"理论依据是什么"，指的是**解释机理用的理论**，不要求你有完整理论框架；备好一句话说明借用了哪个理论。
- 【SCI线】审稿人问 conceptual framework，需要一张图加一段文字明确变量关系及其依据。

## 二、变量与构念的操作化

材料 / 冶金里"构念"通常对应四类：① 组织特征（晶粒尺寸、相组成与体积分数、织构、夹杂物形态）；② 缺陷类型（位错密度、空位、孔洞、裂纹）；③ 工艺变量（温度、时间、冷速、变形量、气氛分压）；④ 性能指标（强度、硬度、韧性、耐蚀、导电、疲劳寿命）。

**从概念到可测量，三步**：
1. **命名**：写下你真正关心的抽象词（如"组织均匀性"）。
2. **定维度**：拆成可分别测量的方面（如晶粒尺寸分布标准差、第二相分布偏析度）。
3. **定测法与单位**：写明设备 + 方法 + 单位 + 取样数（如「金相 + ImageJ 统计 N≥300 个晶粒，取等效圆直径均值，单位 μm」）。
- 自检一句：**换个人拿这段描述，能否独立测出同一个数？** 不能就是没操作化。
- 【答辩线】操作化写进"实验方法"章即可，可简写。
- 【SCI线】操作化必须进 Methods，给出可复现细节（设备型号、参数、统计量、误差表示）；缺取样数量是常见退稿点。

## 三、假设 / 预期的推导链

**五步链**（缺一步即断链）：文献结论 A（已知）→ 我的体系与 A 的差异 B → 由 A 外推的预期 C → 可观测指标 D → 若为真看到 E / 若为假看到 F。
- 材料研究里的"假设"不写「我假设……」，而写成**可证伪的方向性预期**：
  - 弱写法（不可证伪）：「退火温度会影响性能」。
  - 强写法（可证伪）：「在 400–600 ℃ 区间，随退火温度升高第二相体积分数增大，硬度先升后降，峰值落在 500±50 ℃」。
- 每条预期必须同时写明**反例长什么样**（若峰值不在该区间，说明机理假设错，需转向）。
- 【答辩线】写 1–3 条即可；被追问"依据呢"，用第 1 步的文献撑住。
- 【SCI线】预期条数随变量数走，且须在引言结尾显式列出（we expect…），否则易被判"无 hypothesis"。

## 四、框架图该画什么、不该画什么

**该画**：① 输入（自变量：工艺 / 成分 / 原始组织）；② 中间量（实际测得的组织、缺陷，标注测量手段）；③ 输出（因变量：性能指标）；④ 关系箭头——实线 = 本文实测证实，虚线 = 引自文献 / 待验证，箭头旁标方向（如「↑→↑」）。

**不该画**：本文没测的变量（画了就要解释为何没测）；三层以上的层级堆叠（框架图不是流程图）；空泛方框如「材料科学」「热力学」（那不是变量）；与本文无关的全流程工艺链（只画真正对比的那一段）。

## 五、框架 → 章节（框架决定章节，不许反过来）

| 框架要素 | 对应章节 |
|---|---|
| 输入变量及其取值设计 | 实验方法（材料与方案） |
| 中间量及测量手段 | 实验方法（表征）+ 结果 |
| 实线箭头（实测关系） | 结果与讨论（每条箭头一小节） |
| 虚线箭头（文献对比） | 引言（缺口）与讨论 |
| 输出变量与结论 | 结论 |

- 检验法：给框架图每条箭头编号 A1、A2……回目录找哪一节在证它。**找不到节 = 框架虚设，删掉该箭头。**
- 【答辩线】章节可少（绪论 / 实验 / 结果与讨论 / 结论四段），但每条箭头仍须有落点。
- 【SCI线】讨论部分按"每条箭头一节"组织，节标题用变量名而非"讨论一"。

## 六、框架层面常见硬伤（每条附反例）

1. **把研究对象当框架**：反例——框架图只写「研究 6061 铝合金」，没有任何变量与关系。
2. **变量层级混乱**：反例——同一层里既有"冷速"又有"强度"（一个自变量、一个因变量）。
3. **缺中间机理**：反例——直接连「退火温度→硬度」，跳过组织结构，必被问机理。
4. **操作化与结论对不上**：反例——框架声明测"耐蚀性"，结论只给硬度数据。
5. **把预期写成结论**：反例——引言写「结果将表明……」，假设与结果混为一谈。
6. **框架图与章节不映射**：反例——图上有 5 条箭头，正文只讨论了 2 条。
7. **借理论不标适用边界**：反例——用霍尔-佩奇关系解释细晶强化，却在纳米晶区仍套用（该关系在极细晶区失效，**具体临界值未核实**，须自查文献）。
8. **取值区间不可证伪**：反例——预期写成「性能会发生变化」，任何结果都算对。

## 七、验收判据（逐条打勾，全过才算本维度做好）

> **★★★ 判据质量十七条（跨维度通用 · Round 138 补 · 每条都来自本方案自己的踩坑）**
> **⇒ 为什么插在这里**：**对抗审查者（Round 133）用机械探测查出 —— 有 8 条**关于判据本身质量**的修正，**在 11 个维度里零命中**** ⇒ **读者按维度执行时看不到它们，方法论成了只被作者阅读的层。** **⇒ 现把它们收回维度内。**
> **⇒ 用法定级**：**下面八条是**判据的判据** —— 你自己写验收项、设阈值、做检查清单时，**先过这八条**。**

| # | **规则** | **一句话用法** |
| --- | --- | --- |
| **1** | **只有反例的清单会失去区分力**（修正二） | **清单里既要有反例也要有正例** —— 全是「不要怎样」，读者无法判断「做对了是什么样」 |
| **2** | **判据必须「范式感知」**（修正二十） | **每条判据声明适用范式**（例：理论 / 计算类不适用「报 n」） |
| **3** | **判据必须「平台感知」**（修正二十一） | **阈值须注明在哪些平台验证过** —— 同一判据在不同出版平台可能给出**相反**结论 |
| **4** | **判据要「可检出率」感知**（修正二十二） | **≈100% 才能做「缺一即不合格」的门槛；70–99% 只能做提示；<70% 不可用** |
| **5** | **阈值太松 = 没有区分力**（修正十七） | **一个永远合格的阈值不产生信息**；且**阈值必须绑定可执行动作**，只给数字不给动作等于无效 |
| **6** | **从不改变决定的判据，不该当闸门**（修正二十九） | **自检**：**这条判据**有没有可能判出「不合格」**？**从来没有 ⇒ 它只是仪式，删掉或降为提示 |
| **7** | **会「误报」的闸门，与会「漏报」的一样有害**（修正四十七） | **凡闸门须用**两侧样本**验**（一组已知合格 + 一组已知不合格）；**阈值与工具绑定 ⇒ 换工具必须同期重标定** |
| **8** | **验收判据要与「失败形态」配对**（修正四十六） | **判别式**：**第二个人**不看你的稿**，能不能说出「什么算不合格」**？**不能 ⇒ 这条判据还没写完** |

| **9** | **「端到端干跑」是一种独立的验证手段**（修正二十七） | **每个交付物至少真跑一遍全流程** —— **查静态文本不算**；**干跑会发现只看文本看不出的问题**（页面溢出、脚本报错、字段对不上） |
| **10** | **检查器对「被检查的」与「当参照的」用了不同规则**（修正三十三） | **你把 X 和 Y 对比时，**X 与 Y 是否按同一规则被处理**？**不同 ⇒ 结论无效**（本方案实测过：同一个数与两个不同基准比，得出相反结论） |
| **11** | **一次反向测试只能证明「它能报错」，不能证明「它的判据足够严」**（修正五十三） | **做**分级反向测试**：轻度削弱（删一个实例）与重度削弱（删整块）**都试**；**若轻度削弱下仍通过 ⇒ 说明它只要求「存在」不要求「普遍」**** ⇒ **要明确写出这门在防什么** |
| **12** | **「缺失断言」必须指明它相对于哪个输出流**（修正五十四） | **空流会让一切「没找到 X」的断言通过** ⇒ **正负锚必须取自**同一输出流****；**★ 并**保留选错的锚**，以区分「判据报警」与「锚选错了」** |
| **13** | **先证明指标测的是「被测对象」还是「测量链上的某一环」**（修正五十五） | **看**峰的位置****：**若 53% 的值挤在某个宽度上，而那个宽度是**上游工具的**参数**（如提取器的换行宽度）⇒ **你测的是上游**；**小 n（<30）不要用 CV，直接看直方图形状** |
| **14** | **「唯一来源」与「独立检验」在同一进程内不可兼得**（修正五十六） | **唯一来源 ⇒ 自检**恒过**（修正四十三）；**独立构造 ⇒ 必须复制 ⇒ 会漂移**（修正四十九）** ⇒ **三条出路**：①接受「非独立但**会失败**」的自检（只测内存以外的对象，如磁盘回读）；②**把独立检验移到另一次运行 / 另一个进程**（**这才是正解**）；③若必须同进程独立，**让第二个实现尽量小** |
> **★★★ **正向形式通则（Round 143 补，采纳自同行 月流）**：**凡验收项写的是**否定式**（「不得出现 X」「避免 Y」），**在它旁边写一行 `✓ 正向：<可观察的合格状态>`**。**⇒ 理由（同行原话）**：**「没有正向形式的准入条件只是又一次『我不想要坏的』，但不知道什么是好的。」** **⇒ ★ 本项目实测**：**十一维度 87 个验收项里，纯否定式只有 **3 条（3.4%）**** —— **本项目的验收项**绝大多数本来就是正向可观察的****（**这正是此前几轮「把验收判据写实」累积的结果**）。**⇒ 所以本通则**不是**要去批量改写，而是**给以后新写的验收项立个格式**：**写成否定式时，顺手补正向等价。**

| **15** | **采纳外部建议前，先核它的「前提」在本项目是否成立**（修正五十七） | **把建议翻译成一个可普查的判据**（如「含否定词的验收项占比」），**先量一遍再决定改不改**；**★ 量出来远低于建议者假设 ⇒ 处置定为「立格式」而不是「批量修」**；**★ 普查脚本本身要先自证**（实测：初版把「别人」当否定词，差点去「修」一条本来正确的条目） |
| **16** | **查重工具自身的漏检率，就是「重复」这件事的真实概率**（修正五十八） | **查重说「无匹配」只等于「按你给的那几个词没找到」**，**不等于「没有重复」** ⇒ **判据**：① **查重结果必须与「库里总条数」一起读**（**工具说「无匹配（共 N 条）」时，真问题是「N 条里我为什么确信都不相关」**）；② **★ 补救：未命中时再看一遍全量清单**（**成本几十行，收益是避免一次同题并存**）；③ **★ 判「同题」看**意图**不看**措辞****；④ **发现同题后不要删** —— **加 `superseded` 标记指向后继，并**保留旧条仍成立的部分** |

### 框架完成后的 8 项可数自检

| # | 可数指标 | 合格线（示例，可按目标刊调整） |
| --- | --- | --- |
| 1 | **章节数** | 4–7 个一级节（少于 4 太少，多于 7 通常意味着一节该合并） |
| 2 | **引言占全文比例** | 【SCI】≤ 15%；【答辩】可放宽到 20–30%（若设独立综述章） |
| 3 | **每节是否有「一句结论」** | 每个一级节末尾都应有一句能独立读懂的话（**数出来：句数 = 节数**） |
| 4 | **每个图表是否在正文被引用** | 引用次数 ≥ 1（**未引用的图表要么删要么补引用**） |
| 5 | **每个「本文发现」是否有对应图表号** | 缺口数 = 0 |
| 6 | **每段首句是否为完整信息句** | 抽查 10 段，合格 ≥ 8。**★「完整信息句」的定义见维度 06 的 §6 检查表（本文不重复定义）** |
| 7 | **术语表** | **可数定义：全文「自造缩写 + 非本领域通用术语」的条目数 ≤ 15**（判定法：把候选术语给一位**非本方向**的同学看，他问「这是什么意思」的就算一条）；**且每个首次出现处给定义**。（15 这个数是【作者判断】，**可按目标刊与学科调整**） |
| 8 | **篇幅** | 见 `../期刊投稿要求核实清单.md`（已核实：MT Regular <10 印刷页；ISIJ 10 页 ≈ 10,000 词） |

### 例 · 用这张表查一个真实框架

假设框架是：引言 / 材料与方法 / 结果 / 讨论 / 结论（5 节）。

- **指标 1**：5 节 ✅（在 4–7 内）
- **指标 3**：**要数 5 句话** —— 若「结果」节末尾只有数据没有小结 ⇒ 缺 1 句 ❌
- **指标 4**：若「方法」里有 3 张图但正文只引用了 2 张 ⇒ 缺 1 处 ❌
- **指标 8**：若全文 13,000 词而目标刊上限 10,000 ⇒ **必须砍**（且优先砍引言与讨论的重复部分）

**⇒ 8 项里任意一项不合格 ⇒ 回到框架层改，不要指望写作时补救。**

## 八、★ 实测：5 篇真实论文的章节骨架（「框架 → 章节」有多少种形态）（Round 85 补）

> **为什么补这一节**：**§五讲了「框架决定章节」，但没有真实论文的章节数据 —— 于是读者不知道「一个框架到底会落地成几种章节形态」。**
**以下是反向测里 5 篇真实论文的**实际章节骨架**（本项目手动核对，非自动检出）。**

### 实测：5 篇的章节骨架

| 论文 | 范式 | 实际章节 |
| --- | --- | --- |
| **P1** AA6061 管材 DOE | 实验 + 试验设计 | Intro → Experimental → **Results and discussion（合并）** → Conclusion → References |
| **P2** GH4720Li 断裂韧性预测 | **理论 / 计算** | Intro → **Discussion** → Conclusion（**无独立 Results**） |
| **P3** 机械工程 | 实验 | Intro → **Materials and methods** → … → Conclusion → References |
| **P5** Al7075-WC 复合材料 | 实验 | Intro → Methods → … → Conclusion → References |
| **P7** 球化珠光体钢 | 实验 | Intro → **Experimental** → **Results** → **Discussion** → Conclusion → References |

### ★ 三条从这张表里读出来的事

**① 「Results / Discussion 分开」不是唯一形态 —— 5 篇里有 3 种不同形态：**

| 形态 | 出现在 | 为什么这样 |
| --- | --- | --- |
| **Results + Discussion 合并** | P1 | **工艺优化/DOE 类** —— 每个响应变量都要「先给值、再解释为什么」 |
| **只有 Discussion（无独立 Results）** | P2 | **理论/计算类** —— 没有「一批实验结果」需要集中呈现 |
| **Results 与 Discussion 分开** | P7 | **机理研究** —— 证据链长，混在一起会打断叙事 |

**② 方法节的标题有 3 种写法**（`Experimental` / `Materials and methods` / `Methods`）—— **不影响框架，只是刊的惯例差异。**

**③ ★ 骨架的**形状**由研究类型决定，不是由刊决定** —— **同一批刊（Frontiers）里 P1 用合并节、P3 用独立方法节，因为研究类型不同。**

### ★ 本节给本维度加的可执行动作

| 动作 | 判据 |
| --- | --- |
| **1. 先定研究类型，再定骨架** | 在 §五「框架 → 章节」之前，**先写下本文属哪类**：实验+试验设计 / 实验+机理 / 理论计算 |
| **2. 三类对应的默认骨架** | **试验设计类 ⇒ 可用 Results+Discussion 合并；机理类 ⇒ 分开；理论计算类 ⇒ 可无独立 Results** |
| **3. 骨架定了才画框架图** | **框架图里的每条箭头，都应该能在骨架上找到落点** —— 找不到落点的箭头，说明框架里有悬空的主张 |

## 九、★★★★ 一个**真实框架的完整实例**（从一篇真实论文反推 · Round 107 补）

> **为什么补这一节**：本维度前面七节讲的都是「框架应该怎样」——**而 §可数清单 自己写着「含具体数字仅 2 处」，是 11 个维度里最少的。**
> **⇒ 没有实例，读者无法判断自己搭的框架算不算「搭好了」。**
> **⇒ 本节拿一篇**真实发表的论文**，从它的标题与摘要**反推**出它的框架，再把它**逐条映射到章节**。**

### 一、论文信息（可核对）

| 项 | 内容 |
| --- | --- |
| **标题** | **Deformation and Fracture Behaviors of Spheroidized Pearlitic Steel under Tensile Loading** |
| **载于** | **J-STAGE · ISIJ International**（本方案反向测用的 P7） |
| **研究类型** | **实验 + 机理**（按 §八 的分类 ⇒ 骨架应为 Results/Discussion **分开**；实测确实分开） |

### 二、★ 从摘要反推出的框架（**五层链，不是五个并列变量**）

**摘要是逐句读的，下面每一行都对应摘要里的一句或几句（**引号内为原文**）：**

```
【输入·工艺】        spheroidization time（球化时间）
        ↓
【中间量·组织】      ① cementite roundness（渗碳体圆度）↑
                   ② cementite area fraction within a colony ↓
                       —— 原因：「Many coarse cementites were observed on the
                          colony and block boundaries」（粗大渗碳体在晶界/块界）
                   ③ crystallographic orientation relationship between ferrite
                      and cementite（铁素体-渗碳体的取向关系）
        ↓
【实测行为】         「inhomogeneous strain distribution in a unit of the colony」
                    （以「colony 为单位」的不均匀应变分布）
        ↓
【细观事件】         「numerous voids or cracks ... tended to nucleate from the
                    high-strain region」（孔洞/裂纹优先在高应变区形核）
                    —— 机制：「The strain gradient between the soft ferrite and
                      hard cementite phases induced void or crack nucleation
                      around the coarse cementite」（软硬相间的应变梯度）
        ↓
【宏观输出】         「The strength–ductility balance deteriorated」
                    （强度-塑性匹配恶化）
        ↓
【总结论】           「inhomogeneous cementite spheroidization results in an
                    inhomogeneous strain distribution, which causes the
                    preferential nucleation of voids or cracks in the high-strain
                    colony」（不均匀球化 → 不均匀应变 → 高应变区优先形核）
```

### 三、★★★ 两个 MUST：这张框架教给我们的两件事

**① ★ 它是**链**（A→B→C→D），不是**星形**（工艺→性能）。**
**⇒ 对照 §六 硬伤第 3 条「缺中间机理：直接连『退火温度→硬度』，跳过组织结构」—— 这篇论文的框架**在中间放了三个组织量**（圆度 / 面积分数 / 取向关系）。**
**⇒ 这就是「有中间机理」的**具体形态**，不是一句口号。**

**② ★ 结论不是「A 影响 B」，而是「一条**通路**」。**
**⇒ 它的总结论写成：`不均匀球化 → 不均匀应变 → 高应变区优先形核`  —— **三个箭头串起来的一句话**。**
**⇒ 对照 §三 的「五步链」：**这篇论文的结论句正好是那条链的**压缩版**。****

### 四、★★ 框架 → 章节的**逐条映射**（用 §五 的检验法真的做一遍）

**§五 说「给框架图每条箭头编号 A1、A2……回目录找哪一节在证它」。下面**真的做一遍**（章节树见维度 03 §3.9）：**

| **A2** | 球化时间 ↑ ⇒ colony 内渗碳体面积分数 ↓（粗大渗碳体跑到界上） | **§2.2 Microstructure Observation + §3.1** |
| **A3** | 球化 ⇒ 强度-塑性匹配恶化 | **§2.3 Tensile Test + §3.1** |

## 十、★★★★★ **不是每项研究都需要框架 —— 而「机构要求」不等于「方法论规律」**（Round 156 一手核实）

> **为什么补这一节**：**前九节讲的是「框架该怎么建」。本节讲**一个更前置的问题**：**你这项研究**到底需不需要一个框架**。**
> **⇒ 为什么这在材料/冶金方向特别要紧**：**本方向的论文**经常是**实验驱动、描述性的**（**一张 TEM、一组力学曲线、一个成分-性能关系**）**⇒ 硬套一个理论框架**不是为了做好研究，**而是为了填一个章节** —— **而答辩时被问「你的理论框架是什么」，编出来的那个东西恰恰最容易被追问穿**。**

### 一、**一手材料**：一篇专门回答这个问题的指南

**⇒ 来源**：**Manuel B. Garcia《Does Every Research Study Need a Theoretical or Conceptual Framework?》**（`manuelgarcia.info/guides/research`，**Part 03 · Guide 46 of 223** · **HTTP 200 · 2026-10-09**）。

**⇒ 官方原话（本节最重要的一段）**：

```
Not every research study needs a named theoretical or conceptual framework in the same form.
What matters is whether the study has a defensible intellectual foundation and whether an
explicit framework genuinely helps shape the research rather than being added merely to
satisfy convention.
```

**⇒ 它的「短答」原文**：

```
No. Not every research study necessarily needs a formally named theoretical or conceptual
framework, and whether one should be used depends on the research question, methodology,
purpose, disciplinary conventions, and institutional or publication requirements.
```

**⇒ ⇒ ★★★ 但同一段也给了**不可退让的那一半****：**`Every defensible study still needs an intellectual rationale`**（**每一项站得住的研究仍然需要一个**智识理据****）**。**
**⇒ **⇒ 关键区分**：**`The absence of a named theory and the absence of intellectual grounding are not the same condition.`**（**「没有具名理论」与「没有智识根基」不是同一件事**）**。**

### 二、★★★★★ **两条可机械检查的判据**

#### 判据一：**删除测试**（**这是本节最有用的一条**）

**⇒ 官方原文**：

```
Imagine deleting the framework from your proposal. Would your research questions change?
Would you select different constructs, participants, measures, interview questions,
observations, analytical categories, or interpretations?

If the answer is yes, the framework is probably doing substantive intellectual work.
If absolutely nothing would change, the framework may have been added after the research
design was already complete.
```

**⇒ ⇒ 用法（**可执行、可留痕**）**：**把框架整节删掉，然后逐条对**七个位置**看有没有变化**：
**⇒ `研究问题` · `构念/变量` · `测量或取样` · `访谈提纲` · `观察记录` · `分析类别` · `解释`。**
**⇒ **七个位置全无变化 ⇒ 这个框架是装饰**，**应删掉或重写**（**不是保留**）。**
**⇒ ★ 官方给的判据句**：**`A framework earns its place by helping the researcher think, design, analyze, or explain more coherently. Its value does not come from occupying several pages between the literature review and methodology.`**

#### 判据二：**机构要求 ≠ 方法论规律**

**⇒ 官方原文**：

```
But an institutional template is evidence of a reporting requirement,
not proof of a universal methodological law.
```

**⇒ ⇒ 对本方案的直接含义**：**答辩线的学校模板要求「理论框架」一章**，**这是**要求**，不是**规律**** ——
**⇒ **处置**：**`Meet the requirement, but select and present a framework that remains coherent with your research question and methodology.`**（**满足要求，但选的框架要与你的研究问题和方法保持连贯**）。**
**⇒ ⇒ ★ 不要做的是**：**`Do not select a theory simply to fill a required section.`**（**不要为了填一个必需章节而选一个理论**）。**

### 三、★ **六类常见误解**（**官方逐条列出，此处照录并译**）

| # | 误解（官方原文） | 为什么错 |
| --- | --- | --- |
| **1** | **`Every study must have a named theory`** | **需要的是**站得住的智识根基**，**那不等于每一项设计都必须有个具名理论**** |
| **2** | **★ `If there is no theory, you can simply call the diagram a conceptual framework`** | **`A conceptual framework is not a fallback label for an unsupported collection of boxes and arrows.`**（**把变量画成流程图，本身并不构成一个有意义上的概念框架**）** |
| **3** | **`Adding a famous theory automatically makes the study stronger`** | **`A prestigious or frequently cited theory can still be poorly suited to a particular research problem.`** |
| **4** | **`The framework only needs to appear in the literature review`** | **真的在指导研究的框架，其影响应**在别处可见****（**问题 / 假设 / 构念 / 工具 / 编码 / 解释 / 讨论**）** |
| **5** | **★ `Using a framework is always better than not using one`** | **`The same focusing effect can also become a limitation.`**（**框架会聚焦，**聚焦同时也是遮挡****）** |
| **6** | **★ `If your supervisor requires a framework, the methodological debate no longer matters`** | **`A required section does not justify selecting an arbitrary theory.`** |

### 四、★ **决策框架**（**官方给的六情形，直接可用**）

| 你的情形 | 该怎么做 |
| --- | --- |
| **明确要**检验 / 应用 / 扩展 / 挑战**一个已有解释** | **显式理论框架通常是研究的核心** |
| **多组文献概念需要组织，但**没有单一理论**能代表这个问题** | **自己构造的**概念框架**更合适**（**但要**有据**：概念须来自文献 / 实证 / 方法学推理 / 明示假设**） |
| **主要是**描述性**研究** | **先问框架除了**清晰定义 + 相关文献 + 方法学推理**之外还贡献了什么** ⇒ **不要自动加上解释性理论** |
| **方法学强调**归纳发现**** | **考虑早引入详细框架是否会**过早约束**它** ⇒ **理论可稍后进入** |
| **机构 / 导师 / 基金 / 目标刊**明确要求**** | **满足要求，但所选框架须与研究问题和方法**保持一致**** |
| **你确定某个理论合适** | **下一步不是挑最有名的那个** ⇒ **理论应澄清研究，而不是要你改写研究去迁就它** |

**⇒ ★ 官方给的一条自检**：**`You should also be able to state the framework's job in one or two sentences.`**
**⇒ 如果**说不清它改变了、指示了或澄清了什么** ⇒ **重新考虑它为什么在那里**。**

### 五、★ 本节给本维度加的验收项

**⇒ ① **做一次删除测试**，把七个位置（**研究问题 / 构念 / 测量 / 提纲 / 观察 / 分析类别 / 解释**）逐一对照，**记录哪几个真的变了**。**
**⇒ ② **★ 用一两句话写出「这个框架的工作是什么」** —— **写不出来 ⇒ 记为不合格**。**
**⇒ ③ **若结论是「本项研究不需要具名框架」，就**明说不需要**并给出**智识理据**（**定义 / 测量依据 / 相关文献 / 方法学推理**）** —— **不要用「没理论就把框图叫概念框架」蒙过去**（**误解 2**）。**
**⇒ ④ **★ 区分两种驱动力**：「**方法上需要**」还是「**模板上要求**」** —— **后者照办，但要在文中说清它是**报告要求**，**并保证框架与问题方法连贯**。**

### 一、★★ 反向大纲法：**先定图表清单 → 再定子标题 → 最后写正文**（本节**新增**）

| 序 | 动作 | **完成判据（可观察）** |
