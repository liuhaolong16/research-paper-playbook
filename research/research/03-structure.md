## 3.1 体例选型

- **IMRaD**：单一问题、单条证据链的期刊实证短文 —— 材料/冶金 **SCI 默认体例**。
- **IMRaD+**：在其上把 Conclusion 独立成节，多数材料刊如此；能否分以目标刊 Instructions for Authors 为准。
  > **★★ Round 167 补（T3 · 对抗审查者查出）**：**`07-abstract.md` §7.13 的「摘要逐句分配表」把**结论句**锚到 **Discussion****，**而本节判定**多数材料刊用 IMRaD+**（**Conclusion 独立成节**）** ⇒ **两处对「摘要的结论句对应正文哪一节」给出了**不同答案****。
> **⇒ **统一口径**：**摘要的结语句**对应的是**你实际采用的体例里的那一节**** ——**
> **⇒ ⇒ **IMRaD**（Conclusion 不独立）** ⇒ 结语句对应 **Discussion 的末段****；**
> **⇒ ⇒ **IMRaD+**（Conclusion 独立成节，**多数材料刊如此**）** ⇒ 结语句对应 **Conclusion 节****。**
> **⇒ ⇒ ★ 处置**：**先按本节选定体例**（**以目标刊 Instructions for Authors 为准，见 §3.1 第 2 条**），**再回 `07-abstract.md` §7.13 判断该句时态**。**

  **⇒ 所以「分还是合」取决于**论文类型**（机理类分开 / 工艺优化与 DOE 类合并），**不取决于刊的高低** —— 详见 §3.9 第四节。
  **⇒ 另：目标刊用词也要查** —— 实测那篇用的是 `Experimental Procedure`，**不是** `Materials and Methods`（§3.9 第二节第 4 条）。

## 3.2 答辩论文章节与交付物

1. **绪论**：背景、现状、空白、本文问题、技术路线 → 交付：路线图 + 编号问题清单
2. **综述**：按主题分块，末列研究空白表
3. **材料与方法**：原料、设备、工艺参数、表征、数据处理 → 交付：可复现参数表
4. **结果与分析**：按变量分节，每节图表 + 文
5. **讨论**：机理、文献对比、局限
6. **结论与展望**：3–5 条结论对应问题，展望留未解问题
7. 参考文献、致谢、附录（原始数据/补充图表）

**【差异】SCI** 去掉第 2/5/7 章的综述与致谢，Discussion 与 Conclusion 常分节，无「展望」节。

## 3.3 篇幅配比与分合

SCI 常见区间【**作者判断**】：Intro **10–15%**、Methods **15–25%**、Results **25–35%**、Discussion **20–30%**、Conclusion **5–10%**（Abstract 150–250 词另计；硬上限以目标刊为准，**未核实**）。

**★ 使用注意（Round 82 红队第 5 条指出的一处算术问题）**：**上述各节【上界】相加 = 15+25+35+30+10 = 115% > 100%。**
**⇒ 因此这些区间【不能同时取上界】—— 它们是**各节单独看时的常见范围**，不是一组可同时满足的分配方案。**
**⇒ 落地做法：先定 Results 的占比（它决定证据量），再从剩下的额度里分配给其余四节；**
**⇒ 或直接用下面这组**合计 = 100% 的示例分配**（【作者判断】，按目标刊与数据类型调整）：**

| 节 | 示例占比 |
| --- | --- |
| Intro | 12% |
| Methods | 20% |
| Results | 30% |
| Discussion | 28% |
| Conclusion | 10% |
| **合计** | **100%** |

方法/结果分合：方法非创新点 → 压进 Methods 或补充材料；方法即创新 → 独立成节写全参数。
结果与讨论分合**三问**：①讨论需引 ≥3 篇文献对比？②插入会打断结果叙事？③刊模板强制分开？**任一「是」即分开。**

## 3.4 章节内部逻辑

**绪论漏斗**：宏观背景 → 领域现状（3 块，每块一句「已解决」）→ 空白（「然而/尚未报道」指向可证伪缺口）→ 编号问题 → 技术路线。**自检：每段末句能推出下段首句。**
**讨论四段**：重述关键结果（1 句）→ 与文献对比（一致/矛盾 + 原因）→ 机理归因 → 局限与边界；每条结论挂图/表号。
**结论**：不引新数据、不引新文献，**条数 = 绪论问题数**。

> **★★★ Round 167 补（对抗审查者查出的**悬空引用**）**：**下面两条来自国标 **GB/T 7713.2—2022**，而 `07-abstract.md` §7.14 曾把它们的落点**写成「维度 03」**、**但既**此前 03 全文 0 命中**** —— **★ 那是**悬空引用**：**执行者被告知「这条属结构维度」**，**来了却找不到****。**现在落地在本节**。**
> **⇒ ① **`结论是对研究结果和论点的提炼与概括，**不是摘要或主体部分中各章、节小结的简单重复**，宜做到客观、准确、精练、完整。`**
> **⇒ ⇒ ★ 处置**：**写完结论后，把它与**每一节的末句**并排放** —— **若有哪一条只是某节小结的改写**，**删掉或提升到「跨节」的层面**（**结论要回答的是**全文的问题**，不是**某一节做过什么****）。**
> **⇒ ② **★ `如果推导不出结论，也可没有"结论"而写作"结束语"，进行必要的讨论，在讨论中提出建议或待研究解决的问题等。`**
> **⇒ ⇒ ★ 这给了「**实验做了但没得出强结论**」类论文一条**合规出路** —— **不必硬编结论**。**
> **⇒ ⇒ **但注意**：**改称「结束语」**不是免检**** —— **它仍须**覆盖绪论提出的全部问题****（**见 §3.7 的例外条款**）**。**

## 3.5 图表与正文分工

| 必须画图 | 必须进表 | 只能留正文 |
| --- | --- | --- |

## 3.7 验收判据（维度 03）

> **★★★ 判据质量十七条（跨维度通用 · Round 138 补 · 每条都来自本方案自己的踩坑）**
> **⇒ 为什么插在这里**：**对抗审查者（Round 133）用机械探测查出 —— 有 8 条**关于判据本身质量**的修正，**在 11 个维度里零命中**** ⇒ **读者按维度执行时看不到它们，方法论成了只被作者阅读的层。** **⇒ 现把它们收回维度内。**
> **⇒ 用法定级**：**下面八条是**判据的判据** —— 你自己写验收项、设阈值、做检查清单时，**先过这八条**。**

| # | **规则** | **一句话用法** |
| --- | --- | --- |
| **1** | **只有反例的清单会失去区分力**（修正二） | **清单里既要有反例也要有正例** —— 全是「不要怎样」，读者无法判断「做对了是什么样」 |
| **2** | **判据必须「范式感知」**（修正二十） | **每条判据声明适用范式**（例：理论 / 计算类不适用「报 n」） |
| **3** | **判据必须「平台感知」**（修正二十一） | **阈值须注明在哪些平台验证过** —— 同一判据在不同出版平台可能给出**相反**结论 |
| **4** | **判据要「可检出率」感知**（修正二十二） | **≈100% 才能做「缺一即不合格」的门槛；70–99% 只能做提示；<70% 不可用** |
| **5** | **阈值太松 = 没有区分力**（修正十七） | **一个永远合格的阈值不产生信息**；且**阈值必须绑定可执行动作**，只给数字不给动作等于无效 |
| **6** | **从不改变决定的判据，不该当闸门**（修正二十九） | **自检**：**这条判据**有没有可能判出「不合格」**？**从来没有 ⇒ 它只是仪式，删掉或降为提示 |
| **7** | **会「误报」的闸门，与会「漏报」的一样有害**（修正四十七） | **凡闸门须用**两侧样本**验**（一组已知合格 + 一组已知不合格）；**阈值与工具绑定 ⇒ 换工具必须同期重标定** |
| **8** | **验收判据要与「失败形态」配对**（修正四十六） | **判别式**：**第二个人**不看你的稿**，能不能说出「什么算不合格」**？**不能 ⇒ 这条判据还没写完** |

| **9** | **「端到端干跑」是一种独立的验证手段**（修正二十七） | **每个交付物至少真跑一遍全流程** —— **查静态文本不算**；**干跑会发现只看文本看不出的问题**（页面溢出、脚本报错、字段对不上） |
| **10** | **检查器对「被检查的」与「当参照的」用了不同规则**（修正三十三） | **你把 X 和 Y 对比时，**X 与 Y 是否按同一规则被处理**？**不同 ⇒ 结论无效**（本方案实测过：同一个数与两个不同基准比，得出相反结论） |
| **11** | **一次反向测试只能证明「它能报错」，不能证明「它的判据足够严」**（修正五十三） | **做**分级反向测试**：轻度削弱（删一个实例）与重度削弱（删整块）**都试**；**若轻度削弱下仍通过 ⇒ 说明它只要求「存在」不要求「普遍」**** ⇒ **要明确写出这门在防什么** |
| **12** | **「缺失断言」必须指明它相对于哪个输出流**（修正五十四） | **空流会让一切「没找到 X」的断言通过** ⇒ **正负锚必须取自**同一输出流****；**★ 并**保留选错的锚**，以区分「判据报警」与「锚选错了」** |
| **13** | **先证明指标测的是「被测对象」还是「测量链上的某一环」**（修正五十五） | **看**峰的位置****：**若 53% 的值挤在某个宽度上，而那个宽度是**上游工具的**参数**（如提取器的换行宽度）⇒ **你测的是上游**；**小 n（<30）不要用 CV，直接看直方图形状** |
| **14** | **「唯一来源」与「独立检验」在同一进程内不可兼得**（修正五十六） | **唯一来源 ⇒ 自检**恒过**（修正四十三）；**独立构造 ⇒ 必须复制 ⇒ 会漂移**（修正四十九）** ⇒ **三条出路**：①接受「非独立但**会失败**」的自检（只测内存以外的对象，如磁盘回读）；②**把独立检验移到另一次运行 / 另一个进程**（**这才是正解**）；③若必须同进程独立，**让第二个实现尽量小** |
> **★★★ **正向形式通则（Round 143 补，采纳自同行 月流）**：**凡验收项写的是**否定式**（「不得出现 X」「避免 Y」），**在它旁边写一行 `✓ 正向：<可观察的合格状态>`**。**⇒ 理由（同行原话）**：**「没有正向形式的准入条件只是又一次『我不想要坏的』，但不知道什么是好的。」** **⇒ ★ 本项目实测**：**十一维度 87 个验收项里，纯否定式只有 **3 条（3.4%）**** —— **本项目的验收项**绝大多数本来就是正向可观察的****（**这正是此前几轮「把验收判据写实」累积的结果**）。**⇒ 所以本通则**不是**要去批量改写，而是**给以后新写的验收项立个格式**：**写成否定式时，顺手补正向等价。**

| **15** | **采纳外部建议前，先核它的「前提」在本项目是否成立**（修正五十七） | **把建议翻译成一个可普查的判据**（如「含否定词的验收项占比」），**先量一遍再决定改不改**；**★ 量出来远低于建议者假设 ⇒ 处置定为「立格式」而不是「批量修」**；**★ 普查脚本本身要先自证**（实测：初版把「别人」当否定词，差点去「修」一条本来正确的条目） |
| **16** | **查重工具自身的漏检率，就是「重复」这件事的真实概率**（修正五十八） | **查重说「无匹配」只等于「按你给的那几个词没找到」**，**不等于「没有重复」** ⇒ **判据**：① **查重结果必须与「库里总条数」一起读**（**工具说「无匹配（共 N 条）」时，真问题是「N 条里我为什么确信都不相关」**）；② **★ 补救：未命中时再看一遍全量清单**（**成本几十行，收益是避免一次同题并存**）；③ **★ 判「同题」看**意图**不看**措辞****；④ **发现同题后不要删** —— **加 `superseded` 标记指向后继，并**保留旧条仍成立的部分** |
| **17** | **编辑「被程序消费的源文件」前，先确认它的**边界约定****（修正五十九） | **「内容对不对」与「它会不会被读到」是两个独立问题** ⇒ 判据：① **动手前先问这个文件里有没有「程序看的标记」，边界是哪一侧**；② **★「挪到末尾」是危险默认动作** —— **在有边界约定的文件里，末尾恰恰可能是被切掉的那一侧**；③ **★ 每次「看起来等价」的重写都可能**复制不该复制的东西**** ⇒ **切分时先定位标记、明确「标记只留一份且放最后」，不要按语义描述切** |
> **★★ 一条更高层的（它管的是**你做检查这件事本身**）：**
> **⇒ **机械检查的红灯与绿灯都必须交叉确认**（修正十四）** —— **绿灯也要用另一条独立路径复核**，**因为「全部通过」可能只说明检查本身失效**（本方案实测过两次：一次是检查只问「有没有缺口」不问「有没有重复」，一次是流水线被截断后仍打印成功）。**

## 写法示例（Round 37 补）

> **为什么补这一节**：机械审计发现本维度 **4,357 字节、示例 0 处** —— 是 11 个维度里最薄且无实例的一个。
> **本节只给「对的样子」。**

### 例 1 · 结果节的标题要自带结论

- **✗ 不要**：「3.1 硬度测试」—— 只说了做了什么，没说得到什么
- **✓ 应该**：「3.1 时效温度对硬度的影响：峰值出现在 175 ℃」

**⇒ 节标题自带结论方向，审稿人扫目录就能读懂本文的发现。**

### 例 2 · 段落首句要承担「路标」功能

- **✗ 不要**：「由图 3 可知，硬度发生了变化。」
- **✓ 应该**：「硬度先升后降，峰值在 175 ℃/8 h（图 3）。」

**⇒ 首句给完整信息（趋势 + 极值 + 条件 + 图号），后续句才展开细节。**

### 例 3 · 结果与讨论的边界（最容易混）

| 内容 | 该放哪 |
| --- | --- |
| 「硬度为 412 ± 9 HV」 | **结果**（观测值） |
| 「硬度比固溶态高 45%」 | **结果**（由观测值直接算出） |
| 「高于固溶态是因为第二相阻碍位错运动」 | **讨论**（推断） |
| 「与 [A] 报道的峰值温度相差 40 ℃」 | **讨论**（比较） |

**⇒ 判据：句子删去「因为 / 由于 / 这表明 / 与…一致」后仍成立 ⇒ 属结果；反之属讨论。**

### 例 4 · 过渡句的实际写法

- **✗ 不要**：「下一节将讨论。」（无信息）
- **✓ 应该**：「上述硬度趋势无法区分「析出强化」与「固溶强化」，故下一节用 XRD 与 TEM 分别检验。」

**⇒ 过渡句要说清「为什么需要下一节」，而不只是「下面还有一节」。**

### 例 5 · 篇幅与结构的关系（一条已核实的约束）

**★ 已核实实例**：Materials Transactions 规定 **Regular Article 少于 10 个印刷页**；ISIJ International 给出换算 **10 印刷页 ≈ 10,000 词**（含表格、图与其他节）。

**⇒ 结构设计要服从篇幅。** 10 页容量里的常见分配（**示例比例，须按目标刊与数据类型调整**）：引言 ≤ 1.5 页 · 方法 ≤ 2 页 · 结果与讨论 ≥ 5 页。

**⇒ 出处见** `../期刊投稿要求核实清单.md`。

## 3.8 ★ 实测：结构类判据的可检出率与范式差异（Round 77 补）

> **为什么补这一节**：**本维度的判据此前都是「应该怎样」的规定，从未被真实论文检验过。**
> **Round 57–64 拿 5 篇真实论文做反向测时，发现了三个与本节直接相关的事实 —— 它们此前只写在方法论里，没进本维度。**

### 事实一 ★ 章节齐备性无法靠「提取文本里的关键词」自动检查

**两种方法都试过（5 篇真实论文）：**

| 检查 | 旧法（纯关键词） | 新法（编号标题 + 白名单） | 强度裁定 |
| --- | --- | --- | --- |
| Introduction 节 | 4/4 | **5/5** | **可作门槛** |
| Conclusion 节 | 4/4 | **5/5** | **可作门槛** |
| References 节 | 3/4 | 4/5 | **只能作提示** |
| Methods/Experimental 节 | 3/4 | 4/5 | **只能作提示** |
| **独立 Results 节** | **1/4** | **2/5** | **不可用 ⇒ 改人工** |

**根因**：**章节标题在 PDF 里的编码方式因文件而异**（常用不同字体/字号），提取时会被丢失、拆碎或错位。

**⇒ 对本维度的直接后果：§3.7 的验收清单里【没有「章节是否齐备」这一项】** ——
**必须打开排版后的成品**（PDF/Word）**逐节目视确认**，或在投稿系统生成的 PDF 校样上确认。
**⇒ 并建议把「章节齐备」这一项**补进 §3.7 的验收清单**（它是本方案自己发现的缺口）。

### 事实二 ★「Results and Discussion 合并」是真实实践，不是偷懒

**实测：5 篇里 P1（Frontiers, AA6061 管材 DOE 优化）用的就是合并节 `4 Results and discussion`。**

**⇒ 这印证了 §3.3 的「三问分合」是对的，但补充一条：**
**合并节在**试验设计（DOE）/ 工艺优化类**论文里尤其常见 —— 因为每个响应变量都要「先给值、再解释为什么」。**

| 论文类型 | 常见做法 | 理由 |
| --- | --- | --- |
| 机理研究（多表征） | **分开** —— Results 给形貌/结构，Discussion 给机理 | 证据链长，混在一起会打断叙事 |
| **工艺优化 / DOE** | **常见合并** | 每个变量都要「值 + 解释」配对，分开会来回跳 |
| 理论 / 计算 | 常无独立 Results 节 | 见事实三 |

### 事实三 ★ 理论/计算类论文可能真的没有独立 Results 节

**实测：P2（GH4720Li 断裂韧性预测，理论/计算类）的实际章节只有 Introduction / Discussion / Conclusion。**

**⇒ 用「必须有独立 Results 节」去卡这类论文，会报出一个【假缺口】—— 不是论文的结构有问题，是判据不适用。**

**⇒ 本维度的「结构齐备」判据必须先声明适用范式（对应方法论修正二十）。**

### ★ 本节给本维度加的三条可执行动作

| 动作 | 什么时候做 | 判据 |
| --- | --- | --- |
| **1. 排版后逐节目视** | 定稿导出 PDF 后 | **Introduction / Conclusion 必须存在**（这是唯一两条可作门槛的）；**其余节缺了就人工判断是真缺还是检出不到** |
| **2. 先声明范式再查结构** | 动笔前 | 在 §3.1 体例选型处**写明本文属哪类**（机理 / 工艺优化 / 理论计算）；**理论计算类不要求独立 Results 节** |
| **3. 合并节的合法性** | 决定分合时 | **工艺优化/DOE 类可正当地用「Results and discussion」合并节** —— 三问任一为「是」仍应分开 |

**⇒ 出处**：`../playbook/99-methodology.md` 修正二十（判据须范式感知）· 修正二十二（判据须可检出率感知）；实测数据见 `../反向测报告.md` v5 与 `_refs/structural-test-v3.json`。

## 3.11 ★★★★★ **摘要 ↔ 正文章节的接口**（Round 167 补 · 对抗审查者查出的**真缺口**）

> **为什么补这一节**：**对抗审查者（B）查出**：`07-abstract.md` §7.13 的「摘要逐句分配表」把摘要的每一句**锚到正文章节**（Introduction / Methods / Results / Discussion），**但那是它在摘要维度里**自建**的映射**；**而本维度（结构）**从未给出这套映射**** —— **`03` 全文 grep「摘要」只有 1 处命中，且是验收项**。
> **⇒ ⇒ ★ 后果**：**一个先读结构维度、再写摘要的执行者，**看不到任何「摘要句 ↔ 章节」的对应关系****；**而先读摘要维度的人，**看到的映射没有结构维度的背书****。**

### 一、★★★★ **映射表（本节是这套映射的**唯一权威源**）**

| 摘要的这句在做什么 | **对应正文章节** | **摘要维度对应节（时态用）** |
| --- | --- | --- |
| **交代领域现状 / 公认事实** | **绪论（背景段）** | **§7.13 · Introduction 第一条** |
| **交代前人做过什么**（**结论仍成立**） | **绪论（领域现状段）** | **§7.13 · Introduction 第三条** |
| **点出空白（gap）** | **绪论（空白段）** | **§7.13 · 未单列**（**★ 见下方 §三**） |
| **交代本文方法** | **Methods** | **§7.13 · Methods** |
| **交代本文数值结果** | **Results** | **§7.13 · Results 第一条** |
| **指本文整体或某个表 / 图** | **Results**（**表图所在处**） | **§7.13 · Results 第二条** |

**⇒ **IMRaD+**（**Conclusion 独立成节** —— **本方案 §3.1 实测「多数材料刊如此」**）** ⇒ 摘要的结语句对应 **Conclusion 节****。**
**⇒ ⇒ ★ 所以**先定体例、再判断摘要的结语句****（**详见 §3.1 与 §3.4**）**。**

### 三、★ **映射表里唯一**不对应**的一行：gap**

**⇒ **国标的摘要四要素**（**目的 / 方法 / 结果 / 结论**，**见 `07-abstract.md` §7.16 五**）**里**没有「空白」这一项****；**而**英文摘要的惯例**（**§7.13**）**也没有单列「gap」句** —— **它通常被并进「交代前人做过什么」那一句里**（**即「前人做了 X，但 Y 尚未报道」**）。**
**⇒ ⇒ ★ 处置**：**gap **不必**在摘要里单独占一句****；**它应当**并入前人那句的转折部分****。**⇒ **若你发现自己在摘要里写了**两句以上的 gap**，**多半是把绪论的内容搬进了摘要**** —— **摘要的 gap 只需要**点出**，**不需要**论证****。**

**⇒ 边界一：模板证据优先级（三种来源冲突时按此排序）**

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| **1** | **用户 / 目标刊的明确规则** | 最高 —— 用户说「按这个模板」，或刊方 Instructions for Authors 写明 |

**⇒ 边界二：弱模板不用于推断「角色级」细节**
**⇒ 什么算弱模板**：**PDF / 图片 / 网页**（**无样式信息**的载体）。
**⇒ 它们能做什么**：提取**文本规则**、判断**单栏 / 双栏**。
**⇒ 它们不能做什么**：**推断字号 / 字体 / 对齐 / 行距这类「角色级」细节** —— 这些必须来自**可解析的模板文件**（`.docx` / `.dotx` / `.tex` / 官方样式表）**或刊方明文**。
**⇒ 无可靠模板时**：**先向用户索要目标模板或明确格式规则**，**按「看起来像」的样子猜是最差的一档**。

**⇒ 边界三：复合任务硬停（排版请求里混进了内容工作）**
**⇒ 触发条件**：同一请求里同时含「**排版**」与**任何非排版需求**（写作 / 润色 / 降重 / 翻译 / 补引用 / 验证引用 / 改数据）。
**⇒ 处置**：**先停** —— 让用户选「**只排版**」还是「**先拆分非排版部分**再进排版」；**排版动作不做内容工作**。
**⇒ 为什么这条重要**：**排版在流程末端** —— 此时**任何内容改动都不会再走检索与核验**（与 `06-content.md` §6.13「成稿层不新增判断或引用」**同源**）。

**⇒ 本节给本维度加的验收项**：

- [ ] **模板规则带来源等级标注**（§3.12 边界一）：每条用到的格式规则都写明它来自「用户 / 刊方明文」「模板提取」还是「内置兜底」。
  - **✓ 正向：格式规则表里每条都带来源等级；用到兜底的地方在交付说明里被点名**
- [ ] **角色级细节未由弱模板推断**（§3.12 边界二）：字号 / 字体 / 对齐 / 行距都来自可解析模板或刊方明文；拿不到模板时已向用户索要。

### 三、分章节攻击题（**按论文每一章预演**）

**⇒ 用法**：**每一章至少准备 1 题**（题库按 §0–§10 分章排列）；**论文里每一节都要能被问到**。
**⇒ 三类高频攻击的模式**（从题库里能读出来）：
**⇒ ① 「是不是多余/太窄/太宽」类**（针对选题与章节）⇒ 用**题目自测结果**（A/B 三问）+ **反向大纲法**（每个子标题都挂着图表，§十一·一）+ **四段闭环编号**（§十一·二）应答。
**⇒ ② 「是不是堆砌/为什么没引某篇」类**（针对文献）⇒ 用**检索策略**（滚雪球 + 近五年占比）+ **引用全读过**应答；**若真没引：坦诚「该文讨论 X，与本研究的 Y 关联度有限，检索中见过并评估过」—— 不硬编**。
**⇒ ③ 「是不是过拟合/参数调得好」类**（针对结果）⇒ **只用方差与显著性回应**（n 个种子 / mean±std / 配对检验 / 独立验证集选参 / 测试集只报一次），**不用「感觉」「大概」**。
**⇒ ④ 诚信类（一稿多投/数据是否本人做）**⇒ **直接、简短、无歧义（「没有 / 是」）+ 可核验证据**，**不绕弯**（越解释越可疑）。

### 四、对抗应答六条策略（「只答不辩」的落地版）

**⇒ ① 先复述问题**（停顿 1 秒 + 「您问的是……对吗？」）⇒ **确认理解 + 争取思考时间**。
**⇒ ② 结构化应答**（能分点就「第一/第二/第三」，每题 30~90 秒）。
**⇒ ③ 会答的直接答，不会的当场认**（「这个问题我考虑过但研究不深，初步理解是……，答辩后补充」）—— **诚实比硬编安全**。
**⇒ ④ 被连续追问不慌**：**追问 = 评委在测你的思考边界，不是否定你**。
**⇒ ⑤ 引用论文定位**（「我在第 X 章第 X 节有详细说明，可以展开」）⇒ **既有依据又显掌控**。
**⇒ ⑥ 数据类问题一律落到「可复现」**（来源 + 测量管线 + 稳定性检验落点 + 「可以现场复现」）。

### 五、★ 演练前的第 0 步：**结果抗压预检**（与 `10-statistics.md` §10.13 联动）

**⇒ 做法**：把 PPT 上**每个结论性数字**与实验记录逐一勾对，**逐项标注两类之一**：
| 标签 | 判据 | **台上规则** |
| --- | --- | --- |
| **硬数字** | 复现得出，**有 mean±std / 显著性检验背书**（过 §10.13 噪声门） | **可以当确定结论陈述** |
| **待补重复** | **单次跑出、尚未多 seed 验证** | **只能说「初步结果」** |
**⇒ 为什么这是第 0 步**：**防止把落在 seed 方差里的数字练得滚瓜烂熟，却在评委一句「你跑了几次、方差多少」下全盘崩**（**这正是本项目 F3 反例的教训**）。

### 六、★ 答辩 PPT 六条（呈现侧，与 §8.2/8.3 的结构与设计铁律互补）
