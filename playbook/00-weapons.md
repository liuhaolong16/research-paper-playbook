# Playbook · 通用武器区

> 从各维度提炼出的、**跨维度复用**的具体武器。每轮对抗后增补。

## 1 · Overclaim 六句式黑名单（来源：红队组 8）

**出现即扣分**，全文搜索替换：

| 禁用句式 | 替换为 |
| --- | --- |
| 显著提高 | 在 X 条件下提高 Y%（n=3，p<0.05） |
| 证实了…机制 | 支持…的推断（并标明由哪张图支撑） |
| 为…提供了新思路 / 新途径 | 直接删，或写成本文范围内的具体结论 |
| 有望用于航空航天 / 汽车轻量化 | 只放展望段，且加「需进一步验证」 |
| 首次发现 | 首次 + 标注检索库/日期/关键词；任一命中即删「首次」 |
| 最佳 | 本文范围内最优（并给条件） |

**自检动作**：交稿前对全文搜这六个词，逐处替换。**摘要里每个数字都必须能在正文定位。**

## 2 · 「证据 → 推断」两栏法（来源：红队组 4）

讨论节里**每一条机理陈述**都写成两栏：

| 证据（可核对） | 推断（本文主张） |
| --- | --- |
| 具体图号 + 观察到什么 | 由此支持的解释 |
| 若证据不足 | **降级为「推测」，并写明需要什么实验才能确认** |

**为什么有效**：审稿人判「过度解读」时，通常不是反对你的结论，而是反对**结论强度超过证据强度**。两栏法把强度对齐这件事变成可见的。

## 3 · 图表删除测试（来源：红队组 5）

对每张图表问一句：**「删掉它，哪条结论会消失？」** ——**不消失就删。**

附带自检：SEM 图必须有标尺/放大倍数/(a)(b) 标注/图注条件；表必须有单位、误差标 SD/SE。

## 4 · 「一次说清」检验（来源：红队组 1）

能否**一句话**说清「别人没做过什么」？
- 说不清 ⇒ 选题不成立
- 说得清但含糊 ⇒ 还要再收敛
- 说得清且可验证 ⇒ 可以进下一步

**这句话的形态**：体系 + 变量 + 指标（三者缺一不成立）。

## 工具纪律（2026-10-08 补）

- **写 Node 脚本后先跑 `node --check <file>` 再执行。** 能机械检查的东西不要靠肉眼。
  （依据：本项目在生成 round-09 时因数组元素漏逗号导致 SyntaxError，一次失败；同类脚本错误已出现多次。）
- **台账/回执里的 id（msg_id、SHA、版本号）必须以命令行输出为准，不得凭估计填写。**
  （依据：2026-10-08 台账 msg_id 误填事件——「看起来填全了 ≠ 真的填对了」。）

## ★ 可执行性分级（Round 13 新增，用于清理「正确的废话」）

**起因**：Round 09 的红队对本方案做占位符测试时，指出 8 条「读起来对、但删掉不影响任何人行为」的条目。
**处置原则**：**能具体化的具体化；不能具体化的标注为「叙事」并从验收清单移除；重复的指向已具体化的位置。**

### 三级分类（今后所有条目按此归类）

| 级 | 定义 | 处置 |
| --- | --- | --- |
| **A · 可执行要求** | 读者能照着做，且做完能判断过没过 | 保留在验收清单 |
| **B · 需补参数** | 方向对，但缺**具体阈值/对象/来源** | **补参数后升 A；补不了就降 C** |
| **C · 叙事 / 提醒** | 说了正确的道理，但不改变任何动作 | **移出验收清单**，留在正文当背景 |

### 对那 8 条的逐条处置

| # | 原条目 | 级别 | 处置 |
| --- | --- | --- | --- |
| 1 | 「阶段 0 决定上限，阶段 5 决定下限」 | **C** | **降为叙事**（它是记忆点，不是要求）。**理由**：无法据此判断「我做没做到」 |
| 2 | 「从第一次检索起就用管理软件」 | **A** | 保留。**已具体化**：检索式/命中数/纳入数**必须留痕**（无留痕=不可复现） |
| 3 | 「每章末有过渡句」 | **A** | 保留。**可判断**：每章最后一段是否指明下一章做什么 |
| 4 | 「坐标轴不作视觉欺骗」 | **B→A** | **已具体化（见维度 11.6）**：断轴须标断轴符号 / 对数轴须声明 / **纵轴不从 0 开始且未说明即不合格**。**本条改为指向该处** |
| 5 | 「同给 Δ 与工程意义」（无定义无阈值） | **B→A** | **补参数**：同时给出**数值差**与**相对误差**，并写明该差异**是否超过材料重复性范围**（如 ±5 HV）。**否则「有工程意义」无法判断** |
| 6 | 「不用第三方免费工具自我安慰」 | **C** | **降为提醒**。**理由**：它禁止一件事，但不指定该做什么；**可执行版本已存在于维度 09**：查重必须用**学校/期刊指定的系统** |
| 7 | 「题目落在导师能签字范围内」 | **B→A** | **补对象与动作**：阶段 0 **与导师确认一次**并记录（日期 + 结论）。**这样它才是可判断的** |
| 8 | 「结论强度不超证据强度」 | **B→A（已有具体版）** | **已具体化（见维度 10.5）**：三级证据门槛（仅相关时禁用「提高/导致/引起/决定/因为」；有受控干预才可用「使…由 x 提高到 y」；有机制证据才可「归因于」）+ 全文检索那五个词的**动作**。**本条改为指向该处** |

**⇒ 清理结果：8 条中 4 条保留（A）、3 条已具体化或指向具体处（B→A）、2 条降为叙事或提醒（C）。**
**⇒ 从验收清单中移出的是第 1 条与第 6 条**；其余进入验收清单时必须是具体动作形式。

### 一条通用判据（今后写任何条目都用）

> **写完一条要求，问自己：读者照它做之后，能不能指着某个东西说「这条我没做到」？**
> **答不出 ⇒ 它是 C 级叙事，不该进验收清单。**
